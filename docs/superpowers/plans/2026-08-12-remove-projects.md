# Remove public `/projects` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the Know-Center projects portfolio from the public v2 site while redirecting old URLs to `/publications`.

**Architecture:** Delete the page, nav link, CV tile, content collection, data file, and screenshot assets. Point `/projects` and `/projects.html` at `/publications` via Astro redirects. Update authoring docs and record the decision in PLAN/ACTIVITY. No replacement portfolio until AIR has current shipped work.

**Tech Stack:** Astro 7 (static), content collections (`content.config.ts`), YAML data under `src/data/`, redirects in `astro.config.mjs`.

**Spec:** [`docs/superpowers/specs/2026-08-12-remove-projects-design.md`](../specs/2026-08-12-remove-projects-design.md)

## Global Constraints

- Work only under `v2/` (do not delete v1 `projects.html` or root `images/apps/` until cutover).
- Do not soft-archive `/projects`; the route must not render a page.
- Redirects: `/projects` → `/publications` and `/projects.html` → `/publications`.
- Do not invent a new AIR “shipped systems” section in this plan.
- Leave RecSys keywords, publications, and career copy unchanged.
- Do not hand-edit `v2/.astro/content.d.ts` (regenerated by `astro check` / `astro build`).
- Commit only when the user explicitly asks for a commit (user rule overrides frequent-commit defaults).

In `v2/src/components/Masthead.astro`, change the `nav` array from:

```ts

  { href: '/updates', label: 'updates' },

  { href: '/publications', label: 'papers' },
  { href: '/talks', label: 'talks' },
  { href: '/cv', label: 'cv' },
```

- [ ] **Step 3: Remove the CV projects tile**

In `v2/src/pages/cv.astro`, inside the Output `ul.counts` list, delete this entire `<li>`:

```astro
          <span class="num">20</span>
          <span>systems &amp; case studies</span>
        </a>
      </li>
```

Leave the publications, talks, and service tiles unchanged.

- [ ] **Step 4: Point old project URLs at publications**

In `v2/astro.config.mjs`, replace the redirects block so `/projects.html` no longer targets `/projects`, and add `/projects`:

```js

    // No entry for /index.html: the host already serves that as the root page,

    '/selected_pubs.html': '/publications',
    '/projects': '/publications',
    '/projects.html': '/publications',
    '/services.html': '/service',
    '/speaking.html': '/talks',
    '/experience.html': '/cv',
    '/resume.html': '/cv',
    '/sidebar.html': '/cv',
  },
```

- [ ] **Step 5: Sanity-check the three edits**

```bash

```

Expected: only redirect targets in `astro.config.mjs` (and possibly comments). No masthead or CV link to `/projects`.
