# elacic.me

Personal site of Dr. Emanuel Lacić — Principal Engineer at Infobip, leading Team AI Research (AIR).

Built with [Astro](https://astro.build) 7. Static output, no client-side framework, deployed to
GitHub Pages.

**If you only want to add content, you want [`docs/content-guide.md`](docs/content-guide.md).**
This file covers the project itself.

---

## Running it

```bash
npm install
npm run dev        # http://localhost:4321 — drafts are visible here
npm run build      # static output into dist/
npm run preview    # serve dist/ exactly as it will be deployed
```

| Command | What it does |
| --- | --- |
| `npm run dev` | Dev server with hot reload. **Drafts are visible.** |
| `npm run build` | Production build. Drafts are excluded. Fails on invalid content. |
| `npm run preview` | Serves `dist/` — the last check before pushing. |
| `npm run check` | TypeScript and Astro diagnostics. Should report 0 errors. |
| `npm run image` | Regenerates the AIR research-areas image. Needs Chrome. Rarely used. |

Note the `.npmrc` in this directory: it pins the public npm registry, because a corporate
Artifactory mirror inherited from the global npm config does not serve all the Astro packages.

## How it is put together

```
src/
  content.config.ts     Schemas for all content. The contract everything else relies on.
  data/
    profile.ts          Singletons: identity, career, education, funding, awards, AIR areas
    publications.yml    Every paper — the single source for the list AND the citations
    talks.yml           Talks and slides
    service.yml         Programme committees, reviewing, editorial, supervision
  content/
    updates/            Blog posts. One folder per post, images alongside the text.
    paper-notes/        Plain-language summaries of papers, one per publication
  components/           Astro components, each with its own scoped styles
  layouts/Base.astro    <head>, meta tags, masthead, footer
  lib/
    citation.ts         Generates BibTeX and APA from a publication record
    content.ts          All content queries, including the draft rule
    format.ts           Date and label formatting
  pages/                One file per route
  styles/global.css     Design tokens and shared element styles
public/
  documents/            PDFs keep their v1 /documents/... URLs
  images/               Photos and figures keep their v1 /images/... URLs
  air-areas.png         Generated by `npm run image`, committed on purpose
  CNAME, favicon.svg
tools/
  air/                  Source for the research-areas image
  render-air-image.mjs   Renders it via headless Chrome
scripts/
  add_paper.py          Adds a paper: extracts metadata, verifies it, writes the note
  new_post.py           Scaffolds a blog post
  retag_areas.py        Refresh open-vocabulary topic tags from PDFs
  summarize_papers.py   Plain-language paper summaries
```

### Three decisions worth knowing about

**Content is data, not markup.** In v1 the publication list was hand-written HTML, which is why it
had drifted — inconsistent author initials, a missing year, posters on disk that nothing linked to.
Now every paper is a row in `publications.yml` validated against a schema, and the page, the BibTeX
and the APA string are all derived from that row. They cannot disagree with each other, and a typo
in a venue kind fails the build rather than going live.

**The build fails on bad content.** `reference()` in the schema means a paper note pointing at a
publication that does not exist stops the build. That is deliberate: the failure mode moved from
*silently wrong in public* to *loudly wrong before deploy*.

**Old URLs still work.** The PDFs live in `public/documents/`, so every `/documents/....pdf` link
that exists in the wild keeps resolving. v1's page URLs (`/projects.html` and friends) are
redirected in `astro.config.mjs`.

## Deployment

Pushing to `master` triggers `.github/workflows/deploy.yml`, which builds the site and publishes
`dist/` to GitHub Pages. The repository must have **Settings → Pages → Source** set to
**GitHub Actions** — not "Deploy from a branch", which is how v1 worked.

If a build fails, the previous deploy stays live.

Keep `public/CNAME` (`elacic.me`) — losing it drops the custom domain.

## Adding content

See [`docs/content-guide.md`](docs/content-guide.md). In short:

```bash
uv run scripts/new_post.py "Title of the post"                    # a blog post
uv run scripts/add_paper.py public/documents/2026_Venue_x.pdf     # a paper
npm run dev                                                       # check it
```
